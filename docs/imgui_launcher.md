# Лаунчер на Dear ImGui

Если у игры нет свободно распространяемых ресурсов (проприетарная
игра), их нельзя класть в пакет: пользователь должен сам указать
путь к легально установленной игре. Для этого перед стартом движка
нужен лаунчер — небольшой UI внутри того же процесса. Удобнее всего
делать его на **Dear ImGui**: он легковесный, рендерится через тот
же GLES3 и не тянет внешних зависимостей.

Готовый эталонный пример — в `examples/launcher/` (SDL2 + ImGui,
GLES3); сборка Dear ImGui с фиксами под тач-ввод — в
`examples/imgui/`. Требования к теме оформления — в документе
`docs/imgui-theme-spec.md`.

## Главное ограничение: лаунчер и игра живут в одном окне

Композитор ОС Аврора завершает приложение, чьё окно исчезает хотя бы
на мгновение. Поэтому окно лаунчера — это то же самое окно, в котором
позже развернётся игра. Последовательность:

1. Лаунчер создаёт окно и GL-контекст (SDL2:
   `SDL_CreateWindow` + `SDL_GL_CreateContext`,
   `SDL_WINDOW_OPENGL | SDL_WINDOW_FULLSCREEN_DESKTOP`).
2. Крутится цикл ImGui (вкладки, кнопки).
3. Пользователь нажимает «Старт».
4. Лаунчер отрисовывает **один кадр «Загрузка»** (см. ниже).
5. ImGui корректно выгружается (`ImGui_ImplOpenGL3_Shutdown`,
   `ImGui_ImplSDL2_Shutdown`, `ImGui::DestroyContext`) — он
   освобождает свои VAO/VBO/программу/текстуру шрифта. **Окно и
   GL-контекст при этом остаются живы.**
6. Движок при инициализации видит готовые окно/контекст (лаунчер
   отдаёт их наружу, например через `Launcher_GetWindow()` /
   `Launcher_GetGLContext()`) и **пропускает своё создание окна** —
   иначе приложение будет убито композитором.

### GL-атрибуты окна = атрибуты движка

Окно лаунчера обязано создаваться с теми же параметрами цвета и
глубины, на которые рассчитывает игровой движок, — иначе движок
получит чужой формат буфера. Типичный набор (выставлять ДО
`SDL_CreateWindow`, держать синхронизированным с конфигом движка):

```
SDL_GL_CONTEXT_PROFILE_MASK = SDL_GL_CONTEXT_PROFILE_ES
SDL_GL_CONTEXT_MAJOR_VERSION = 3, MINOR = 0
RED/GREEN/BLUE/ALPHA = 8, DEPTH = 24, STENCIL = 8, DOUBLEBUFFER = 1
```

### Кадр «Загрузка»

Инициализация движка и первая загрузка ресурсов могут занять
секунды. Застывший кадр с нажатой кнопкой выглядит как зависание,
поэтому перед передачей управления движку лаунчер рисует один
полноэкранный кадр с надписью «Загрузка» по центру — и только потом
выгружает ImGui.

## Структура UI

Полноэкранное окно ImGui без декораций (`NoTitleBar | NoResize |
NoMove | NoCollapse | NoSavedSettings`). Сверху — **заголовок с
названием проекта**, ниже — панель вкладок (`ImGui::BeginTabBar`).

### Вкладка «Игра» (базовая)

- Кнопка **выбора расположения ресурсов игры**. Выбор — встроенный
  браузер каталогов на ImGui: текущий путь, кнопки «Выбрать эту
  папку» / «Вверх» / «Отмена» и скроллируемый список подкаталогов
  (каждая строка — крупная кнопка).
- Выбранная папка **валидируется** — проверяется, что она похожа
  на корень ресурсов игры (характерные файлы/подкаталоги движка).
  Статус показывается текстом: «не выбрана» / «ресурсы найдены» /
  «не найдено ...».
- Стартовая папка браузера: `~/Downloads` или `~/Documents` — на
  Авроре туда мапится пользовательское хранилище; последний
  выбранный путь сохраняется и подставляется при следующем запуске.
- После валидного выбора появляются **кнопки запуска**: основная
  игра, а если у игры есть моды/DLC — отдельные кнопки для каждого
  (например, для quake-подобной игры — отдельный запуск каждого
  дополнения). Каждая кнопка стартует движок со своим набором
  параметров (свой мод/каталог).

### Вкладка «Настройки»

Специфичные для порта настройки. Минимум, который почти всегда
нужен, — **коэффициент масштабирования FBO**: слайдер от 0.25
до 2.0 (0.5 = половина разрешения рендера — быстрее, 1.0 = полное,
2.0 = supersample) плюс крупные кнопки-пресеты (0.25 / 0.50 / 0.75 /
1.0 / 2.0). Значение сохраняется в конфиг лаунчера и передаётся
движку (см. «Передача параметров движку»).

### Вкладка «О программе»

- Дисклеймер: порт предоставляется **как есть (AS IS)**, без
  каких-либо гарантий; ресурсы игры не распространяются с
  приложением — игру нужно приобрести легально.
- Приглашение подписаться на телеграм-канал
  [sashikknox Все портит!](https://t.me/auroraosgames).
- Лицензия движка, ссылка на исходники, список сторонних
  компонентов (Dear ImGui и пр.).

## Тач-вёрстка

- Все размеры — от **физического DPI** устройства:
  `SDL_GetDisplayDPI` → dots_per_mm; целевая высота глифа ~3 мм
  (кламп, например, 14–96 px, чтобы нулевой DPI не дал микроскопический
  шрифт); далее `style.ScaleAllSizes( font_px / 13.f )`.
- Кнопки — под палец: высота ~3–3.5 размера шрифта, во всю ширину
  вкладки, чтобы не было горизонтального переполнения в любой
  ориентации.
- Шрифт: системный TTF с кириллицей (диапазоны глифов: Latin-1,
  Cyrillic 0x0400–0x04FF, General Punctuation). Если системного
  нет — встроенный шрифт ImGui с масштабированием
  (`io.FontGlobalScale`).

### Обработка тач-событий

НЕ транслируйте движение пальца в движение мыши — кнопки начнут
«драг-селектиться». Рабочая схема:

- **тап** (суммарное смещение пальца меньше порога, ~16 px) — на
  `SDL_FINGERUP` эмитится пара mouse down+up в точке нажатия;
- **драг** (смещение больше порога) — превращается в импульсы
  `io.MouseWheel` для окна под пальцем (~28 px на тик колеса) —
  так работает скролл списков;
- на `SDL_FINGERDOWN` — только `SDL_MOUSEMOTION` в точку касания,
  чтобы hover-тест ImGui выбрал правильное окно для скролла.

Используйте сборку Dear ImGui из `examples/imgui/` — в ней есть
фиксы под тач-ввод.

## Конфиг лаунчера и песочница

- Конфиг — простой key=value файл (`path=...`, `r_3d_scale=...`)
  в разрешённом песочницей каталоге
  `~/.config/<org>/<app>/launcher.conf` (см. «Пути записи
  (песочница)» в AGENTS.MD). Идентификаторы `<org>`/`<app>` — те
  же, что в `port_config.json` и spec-файле; передавайте их в код
  дефайнами сборки (например, `AURORA_ORG` / `AURORA_APP`).
- Запись вне разрешённых путей песочница **молча проглатывает** —
  путь к ресурсам «потеряется» при следующем запуске.
- `io.IniFilename = nullptr` — иначе ImGui попытается писать
  `imgui.ini` рядом с бинарём (тоже вне песочницы).

## Передача параметров движку

После нажатия «Старт» лаунчер передаёт выбранные значения движку —
удобнее всего через env-переменные, которые движок читает при
инициализации:

- путь к ресурсам (и, если движок различает, read-only путь к
  ресурсам — его же можно зашить флагом в `Exec` desktop-файла);
- коэффициент масштабирования FBO.

Пишущийся корень движка (сейвы, конфиги) обязан оставаться внутри
песочницы (`~/.local/share/<org>/<app>`).
